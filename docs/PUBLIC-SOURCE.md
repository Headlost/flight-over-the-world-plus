# Publiczna dystrybucja źródeł

Pełny projekt deweloperski pozostaje lokalnie. Publiczny eksport pomija moduły wymienionych w scripts/public-source-manifest.json i zastępuje je komentarzami o pominięciu implementacji. Pozostałe śledzone pliki są kopiowane z aktualnej wersji roboczej. Oznaczenia nie zmieniają praw do wcześniejszego kodu projektu, zależności ani wkładu osób trzecich.

Przygotowanie: node scripts/export-public-source.mjs. Wynik jest nowym katalogiem .public-export z README i OMITTED-MODULES.md. Eksport nie zawiera pliku .env.local, historii Git, starych workflow budujących prywatne moduły, odpowiednich testów ani skompilowanej gry. Wykrycie ciągu wyglądającego jak JWT w pliku tekstowym zatrzymuje eksport. Eksport nie jest samodzielnym projektem możliwym do przebudowania bez prywatnej części.

Nie należy wypychać pełnego lokalnego drzewa do skonfigurowanego starego origin `Headlost/flight-over-the-world`. To repozytorium pozostaje publicznym forkiem ze swoją dotychczasową historią; GitHub stosuje widoczność do całego repozytorium, a usunięcie modułu z ostatniej wersji nie usuwa go z historii. Publiczny eksport jest przeznaczony wyłącznie do niezależnego repozytorium `Headlost/flight-over-the-world-plus`, utworzonego bez relacji forka. Nowe repozytorium nie ukrywa ani nie usuwa wersji opublikowanych wcześniej w starym forku.

Gotowa gra wymaga odrębnego procesu publikacji. Kod JavaScript uruchamiany w przeglądarce jest dostępny użytkownikom nawet po minifikacji i bez map źródłowych. Wariant bezpośredniej autoryzacji Vite wstawia tokeny z VITE_CESIUM_ION_KEY do klienta; GitHub Secrets nie ukrywają wartości używanych przez frontend. Nowy wariant brokera pozostawia obie zmienne ion puste, a długotrwałe JWT są używane wyłącznie w prywatnych credentials n8n. Klucz Google i identyfikator sesji potrzebne do bezpośredniego renderowania pozostają dostępne w przeglądarce. Wcześniej opublikowane tokeny i historia nie są przez tę zmianę usuwane.

Referencje: [widoczność repozytoriów](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility), [widoczność forków](https://docs.github.com/en/pull-requests/reference/forks), [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages).

Docelowa publikacja w niezależnym repozytorium `Headlost/flight-over-the-world-plus`: gałąź `codex/public-source` zawiera świeży eksport z pominięciami i jest domyślnym widokiem GitHuba. Gałąź `codex/site` zawiera wyłącznie gotowe pliki `dist` i jest źródłem GitHub Pages (bez ponownego budowania prywatnych modułów). Poprzedni workflow Deploy w starym forku pozostaje wyłączony, aby nie publikował dawnej wersji z `main`. Pełnego lokalnego `main` nie wypychać; jego commity z nową implementacją pozostają lokalne. Zdalna gałąź `main` i historia starego forka nie są usuwane, więc wcześniejsze źródła nadal są publiczne.

Zgodnie z priorytetem użytkownika strumień kafelków pozostaje bezpośredni. Dedykowany workflow n8n obsługuje wyłącznie przydzielanie i odnawianie sesji, bez instalowania dodatkowej usługi lub używania SSH. Zachowanie ostrości i ciągłości zweryfikowano na prawdziwych danych Google przed przygotowaniem dystrybucji. Początkowy root przechodzi pełną inicjalizację osi modeli i elipsoidy SDK bez ponownego root requestu w przeglądarce; odnowienie zachowuje istniejący root, modele i cache. Szczegóły rozliczania stałej pierwszej puli i granic ochrony: docs/N8N-TERRAIN.md.
